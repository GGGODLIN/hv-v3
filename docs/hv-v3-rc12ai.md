# hv-v3 rc12ai

## 已驗證
- **sim 對齊實玩（根因）**：QA rc12ah 的商人事件顯示，玩家在藥水 <8 時會買（94 次買，藥水 ≥8 時 71 次不買）。驗收 sim 原本用 `SIM_MERCHTHR=0`，從來不買，所以低估了 bl/bw。現在 `scripts/rc12ab-accept.ts` 的預設改成 `SIM_MERCHTHR=8`（**自訂**）。改完、還沒調參時，樓層中位 bl/bw/oc/ar 是 80/76/76/71，比舊 sim 更接近實玩的 100/86/69/66。
- **oc 一般戰長尾**：「防禦循環」的假設被否定了。sim 的 oc 防禦回合佔比只有 2.1%。實玩 oc3 F73 那場沒有防禦，是對著暈眩的怪連打很多回合打不死。oc 兩隻怪的 HP 池約是 blade 的 2 倍（每回合傷害 / 最大 HP 是 0.061 對 0.120）。所以改成**下修 oc 小怪 HP**，而不是改防禦邏輯。這和製作人指定的選項 (b)「修防禦循環」不同。
- **arcane F65 首領**：改成提高法術輸出，沒有砍首領 HP。`RUN12AI.arcMdb=1.3`（**自訂**）從 F45 線性升到 F65。arcane 的 `RUN12AH.bossK` 從 0.85 拿掉，回到 1。

## 調參
- r1：上表的設定，但 oc mobK 0.5，oc 一般戰最大 34。
- r2：oc mobK 0.45、mobTo 80，全部達標。共 2 輪。

## 推測
- 單次 sweep 的樓層有約 ±3 層的雜訊。oc mobK 0.45 但不加 mobTo 80 時，最大值是 34，所以 oc 長尾對參數很敏感。
- blade 和 bulwark 的一般戰最大值（38/44）不在目標內，QA 可能會有感。
- 實玩 bl 100 / bw 86 和 sim 仍有差距，可能來自玩家技術，不只是藥水。
