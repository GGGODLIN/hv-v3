# v055 換裝面板預覽：獨立程式驗收

日期：2026-10-28 UTC。範圍：開發候選來源，不代表公開候選或正式頁已完成瀏覽器驗收。

## 結論

`node --test tests/loadout-preview-audit.test.mjs`：12 / 12 通過。
此檔由獨立驗收角色新增，只修改獨立測試與本文件，未修改實作。

預覽以既有面板計算為準，沒有引入新的戰鬥規則、傷害預測或換裝交易。測試的數值 oracle 不是呼叫新 UI helper，而是複製目前進度後實際執行既有 `act(..., 'equip', id)`，再使用 `stats()` 取得真實換裝後面板；pending oracle 先把同件裝備領入測試副本的背包。這些操作不作用於被驗收的 UI 進度。

## 獨立覆蓋

1. 七項可見前後數值與差值，已裝 HP Tank / 單手傷害能力納入計算。
2. 多部位防禦相乘後的一般物理減傷，不誤用原始防禦評級之和。
3. 招架評級提升但面板機率已達 50% 上限時，正確顯示「相同」。
4. 完全相同裝備、負差及低於顯示精度的微小負機率差。
5. `render(false)` 在熟練度、屬性、已裝能力變動後更新，不能留舊值。
6. 背包及待領裝備、唯讀／戰鬥期間、已穿與空選取各狀態。
7. 武器、護甲、飾品及切換所選部位使用正確物件。
8. 配裝記錄保護不妨礙檢視；檢視不解鎖、不改記錄、不回復 HP / MP。
9. 重複重繪不改進度、RNG（整個 state 精確比較）、交易呼叫及儲存呼叫。
10. 說明包含非 DPS／勝率預測、不含武器特效及敵人狀態的邊界。
11. 敗北狀態與既有換裝按鈕的可用性保持一致，不假稱必須先回營。

## 審查發現與修正

- 開始實作前指出：原 inventory signature 不包含角色屬性、熟練度與能力，加入新面板後可能讓非強制重繪顯示舊值。實作加入依賴，獨立測試確認刷新。
- 實作後發現新提示以 `mode !== 'town'` 宣稱必須回營，但既有規則只在 battle 禁止換裝，defeat 仍可操作。獨立測試實際得到 11 pass / 1 fail；實作者將提示條件改為 `mode === 'battle'`，不更動原有引擎規則，再測 12 / 12 通過。
- 測試編寫中的 selector、等值文案及載入時回復生命 fixture 調整，不是產品缺陷，也不列為實作修正。
