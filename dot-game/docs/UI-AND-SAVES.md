# UI 與存檔：v0.2

## 操作與戰術
開啟 `index.html` 對應的 HTTP(S) 網址，選擇路線、營地戰術後「開始遠征」。戰鬥自動進行；回營比較、換裝、出售或鎖定戰利品，再挑戰。戰術是本作適配，不是原版 HV 的自動操作規則；三種策略的描述直接來自獨立 engine。戰鬥中不能改戰術。

## 線上背景掛機
「存檔」內背景線上掛機預設開啟。250 ms 計時器是唯一遊戲時鐘；requestAnimationFrame 僅負責前景繪圖，沒有第二次計算戰鬥。背景分頁仍持有 Web Lock；打開新分頁不會讓舊分頁停戰。

使用單調時鐘計算「兩次實際執行」的間隔：最多處理 2 秒；間隔超過 5 秒整段丟棄，不補算。visibility / ownership 變動會重設計時基線。不以存檔時間計算收益；關閉、重新整理、裝置休眠或瀏覽器凍結都不產生離線收益。瀏覽器可能節流或停止背景計時器，因此背景速度不保證等於前景，更不是伺服器掛機。

關閉背景選項時，隱藏分頁會先存檔並釋放鎖，回到前景再嘗試取得；設定開啟時隱藏只存檔，不釋放鎖。音效預設關閉且背景靜音。減少動畫可手動設定，也尊重系統偏好。

## 單一寫入者
同一存檔命名空間只使用 Web Locks API 的 exclusive lock 決定寫入者，不用 localStorage 過期租約假裝原子鎖。第二個分頁唯讀，顯示最近保存的營地進度，不計戰鬥。支援 BroadcastChannel 時可在「存檔」按「接手此分頁」：原分頁同步保存後釋放鎖，新分頁取得鎖後才讀取最新存檔。原分頁停留唯讀，避免搶回。交接/重新載入從營地安全恢復，不保留戰鬥中敵人。

無 BroadcastChannel 時請關閉持有進度的分頁，新分頁會重試鎖定。不支援 Web Locks 時採安全相容模式：只前景記憶體遊玩，**不寫入共享遊戲存檔**，請手動匯出；不宣稱此模式有跨分頁寫入互斥。瀏覽器拒絕 Lock API 時不取得寫入權，請換用支援安全來源的瀏覽器。

頁面離開時保存並釋放鎖，恢復 BFCache 時重新爭取鎖。不保證瀏覽器崩潰時最後一次保存後的進度；平時每 5 秒保存、有效操作後立即保存。儲存失敗會警告，不宣稱保存成功。

## 存檔與隔離
v0.1 JSON 存檔仍可匯入，但 v0.2 使用全新存檔鍵 `hv-v3-dot-stable-save-v2` 與偏好鍵 `preferences-v2`，Web Lock 亦使用 `writer-v2`。首次沒有 v2 存檔時，只讀取並驗證同命名空間的 `save-v1`，在取得鎖後才另存到 v2；**絕不寫入、刪除或覆蓋 v1**。因此仍開著的 v0.1 分頁不能改壞 v0.2 存檔，無需先手動關閉才能安全升級。

已有 v2 就只讀 v2，不重新套用舊資料；即使 v2 損壞也不拿 v1 默默覆蓋。v1 驗證失敗亦保留原文並阻止自動覆寫，直到匯入有效備份。遷移提示明示：舊版後續進度不自動合併，請在新版繼續或手動匯出。多個 v0.2 分頁同時開始時，只有鎖持有者能寫 v2，接手者取得鎖後重新核對最新 v2，不以啟動時的舊副本覆寫。

候選版 URL `candidates/<id>/` 使用 `hv-v3-dot-candidate-<id>-save-v2`，僅可讀取同候選命名空間的 v1；不會讀取或覆寫正式版。每個命名空間各自鎖定；偏好也隔離。

匯入上限 2 MB，經 engine.validateSave 清洗，再確認並檢查寫入權；唯讀分頁不能匯入或改進度。損壞既有存檔時保留原始資料並禁止覆寫，直到使用者匯入有效存檔。匯出不需要寫入權，可保存當前可見進度。沒有外部帳號、雲端玩家存檔或網路素材依賴。

## 驗證
`npm test` 包含注入時鐘/鎖的 session 測試：只計一次時間、無離線補算、長間隔丟棄、上限、暫停後重設、互斥、交接順序、未支援/拒絕與待取得鎖時取消。靜態 UI 測試驗證 IDs、rAF 無模擬、匯入邊界與相容模式不寫共享存檔。這些不等同真實瀏覽器多分頁、背景節流或發布環境驗收；另看驗收文件。
