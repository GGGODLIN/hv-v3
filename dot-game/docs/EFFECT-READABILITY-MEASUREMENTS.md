候選與 exact v0.33 分別執行相同公開動作；每次動作與 pulse 後核對完整狀態及戰報。**286 個核對點完全相同**，包含隨機狀態，而不只是畫面上的總數。engine、loot、session 逐 byte 不變。

## 控制器驗證

把同一份 canonical 自然進度分別載入 v0.33 與 v0.34，完成 **12 個語意核對點**，每點完整狀態、亂數、動作紀錄與被追蹤的儲存寫入均一致：

- 三個自然武器 ID 各做三次展開／收合、同物品重畫和摘要焦點復原，共九循環；沒有遊戲狀態、資源或持久寫入改變。
- 換成另一個確切物品時收合；再回到原物品不沿用更早的展開狀態。
- 同物品重畫保留展開，但不搶走篩選欄的焦點；把正在查看的戰斧篩出清單時，既有「篩選外」提醒仍在。
- 原始未辨識武器 `starter-weapon` 保留「不會觸發武器特效」，沒有虛構公式展開區。
- 已穿武器 `loot-27` 在唯讀模式仍可查看，摘要焦點只在同一 ID 下復原。
- 查看後經既有控制器正常出征、預約通關回營；**34 個四分之一秒 pulse** 的完整狀態／亂數／動作／寫入一致，雙方都取得第 21 勝。再前進八個 pulse 不自動重啟、不重複發獎。

來源測試 DOM 未內建 `<summary>` 的原生焦點與 `<details>` 的開合。量測腳本只在自己的 adapter 中為建立的 summary 加入可聚焦能力，並設定 `details.open`／送出 toggle 事件。沒有更改 production 或共用 harness 來配合測試；這些是明列的模擬能力，**不是瀏覽器 Tab／Enter／Space 驗收**。

## 重跑

從 `dot-game/` 執行，基點必須是獨立恢復的 exact v0.33：

```sh
BASELINE_DOT_GAME=/path/to/135-v033-publication-receipt \
  node scripts/effect-readability-measurement.mjs
```

預設寫入 [機器可讀收據](measurements/effect-readability-v034.json)。若只做交叉核對，可設定 `EFFECT_READABILITY_OUTPUT=/tmp/effect-readability-rerun.json`，再逐 byte 比較輸出。收據包含完整固定協定、逐場結果、基點與現行輸入 SHA256、腳本 SHA256、文字計數、控制器核對點及限制。歷史量測與 fixtures 不被改寫。

同一份最終 UI（含 `preventScroll` 焦點復原）再次獨立啟動腳本，輸出逐 byte 相同；這是可重現性檢查，仍不是新增一份實際瀏覽器證據。

## 限制

- 模擬 DOM 無法算 CSS 排版、字型、焦點框、viewport、縮放或螢幕閱讀器結果。真正瀏覽器的展開、鍵盤、正常遊玩及公開候選驗收須另做。
- 本 harness 使用不支援 Web Locks 的暫存模式；紀錄寫入一致不等於真實瀏覽器持久存檔或跨分頁控制權驗收。
- 此小樣本沒有自然待領溢出，也沒有實際綁定／IW 交易；各項費用、不可逆警示與保護仍須由獨立來源測試及操作當下驗收覆蓋。
- 20 場全勝只描述預先固定的樣本，不代表新介面提升戰力、掉率、收益或必勝；本次不改任何玩法數值。
