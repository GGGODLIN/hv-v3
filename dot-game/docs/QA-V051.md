# v0.51 manual-sale ceiling regression

Scope: `sell`, `sellSafe`, and legacy `sellCommon` now reject the entire operation before changing money, inventory, pending FIFO, logs, or RNG when proceeds would exceed the existing saved-gold ceiling of 1e12. Exact-cap sales remain valid. A rejected single-item sale retains its comparison and shows a not-sold message.

This is a bug fix to this game's saved economy, not a newly asserted original-HV rule. Prices, protections, loot generation, normal FIFO order, combat, and save schema are unchanged. Other reward and automatic-sale paths are not claimed fixed by this slice.

Evidence:
- 9 focused regression tests: all pass on v051; using v050 engine gives 6 expected failures and 3 passes, reproducing discarded items/unpersistable proceeds.
- 6 independently written audit tests pass, including atomic batch rejection, malformed balances, exact-cap save roundtrip, and production UI handler executed in a DOM model. Against v050 engine, 3 audit cases fail as expected.
- Full suite: 2079 tests passed; no failures/skips. Four runtime JavaScript syntax checks pass.
- Older byte-identity tests still assert their original hashes after an exact inverse of only this slice's changes; gameplay tests execute the live modified engine.

No real-browser playthrough was performed. DOM models are not browser acceptance. This is an unaccepted, unpublished source candidate, not a change to the accepted v036 website. Existing art publication scope remains unresolved. Complete source, inherited required assets/provenance, tests, and recovery instructions are retained; exact-commit backup verification is tracked separately from this source QA report.
