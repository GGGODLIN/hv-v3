# v0.6 安全整理：讓背包晚一點滿，不替你決定配裝

**安全自動出售預設關閉。** 開啟後，只檢查「之後新掉落」的裝備；既有背包、已裝備物品及待領戰利品不會被回頭清理。想整理舊物品，請另外使用有清單與確認步驟的「預覽安全整理」。

這是本作新增的掛機便利功能，**不是原版 HV 的自動出售規則**。原版裝備研究、R 值擬合模型與本作掉落率／售價適配仍分別記錄在 [LOOT-DESIGN.md](LOOT-DESIGN.md)；本次沒有更改品質機率、裝備數值、敵人、戰鬥或背包容量。

## 哪些會賣？哪些一定留下？

必須同時符合以下條件，才可以安全出售：

1. 候選物品**未鎖定**，品質為粗製（Crude）、尚可（Fair）或普通（Average）。
2. 有一件**目前已裝備，或背包中由你鎖定**的物品作為保留者。普通的未鎖定背包物品、待領物品都不能充當保證；候選物品也不能互相保證後一起賣掉。
3. 兩件都是本作能完整辨識的**相同基底**。例如刺劍不會拿戰斧作比較；不同護甲或飾品基底也不混比。
4. 保留者的攻擊、防禦、生命、暴擊、閃避、格擋**六項全部不低，至少一項更高**。沒有的屬性視為零。不用總分、等級或品質高低替代逐項比較。

因此，屬性完全相同、有高有低的配裝取捨、相對保留者更好的升級、優良（Superior）以上品質、鎖定物品，以及身份／欄位不明的物品都不會因這條規則被賣掉。**沒有合格的受保護保留者，就留下。** 售價沿用既有單件公式 `max(1, round(level × 3 + power))`；評分只影響售價，不是出售資格。

鎖定備用裝備有兩個用途：保護它不被出售，也讓之後同型、六項都嚴格不如它的低品質掉落可被整理。只鎖你確實想留下的替代配裝，不必為開啟功能把所有東西都鎖住。

## 使用方式

### 只整理之後的新掉落

1. 回營，檢查已裝備物品；有要留的替代配裝，可先在背包鎖定。
2. 在背包區勾選「**安全自動出售**」，確認狀態顯示「開 · 僅新掉落」。開啟當下不賣任何舊物品。
3. 出發後，符合條件的新掉落直接換成金幣。戰鬥／戰利品紀錄會寫出自動出售與收入；不符合條件的照常入背包。
4. 想停止時先回營，再取消勾選。關閉只影響之後的掉落，**不能復原已完成的出售**；重要進度請先匯出備份。

戰鬥中不能變更設定。唯讀分頁不能調整或出售，必須先取得目前進度控制權。自動出售和「背景線上掛機」是不同設定；開了自動出售不代表關閉頁面後仍有收益。

### 整理背包裡的舊物品

1. 回營後按「**預覽安全整理**」。這不會開啟自動出售，也尚未賣出任何東西。
2. 清單逐件列出名稱、ID、品質、售價、會保留的同型物品，以及哪些屬性更好；核對件數與合計金額。
3. 按「取消，返回背包」、右上角關閉或 Escape，都不會出售。
4. 確認後只出售**這份預覽列出的 ID**，不會擅自補入後來符合條件的物品。確認前若裝備／鎖定／保留條件改變，或失去分頁控制權，整批取消；請重新預覽。

清單為空時不能確認。重複確認不會重複收款。手動批次與自動新掉落共用保守資格，但彼此是兩個獨立操作。

## 存檔與跨版本限制

- 新遊戲與沒有此設定的舊存檔都維持關閉。有效 v0.6 存檔只有明確的布林值 `autoSell: true` 會保留開啟；缺欄位、字串或其他值不算同意。
- v0.6 沿用既有 v3 儲存／分頁寫入命名空間，不另開一份正式進度。舊版分頁仍執行舊程式；若由舊版接手並保存，可能移除新設定。回到 v0.6 時請檢查開關，不要假設跨版本會自動合併。
- 匯入會取代目前進度，先備份並核對確認提示；載入後安全回營，不補算離線時間。先前開著的整理預覽不能沿用。
- 裝備含本版不支援的額外欄位、未知屬性／R 欄位或不支援格式時，**整份匯入拒絕**，不先刪欄位、不暗中加鎖，也不把它改造成可出售物品。請保留原始存檔，改用能理解該版本的程式；匯入失敗不改目前進度。
- 可載入但無法辨識身份的裝備仍可保留，不會因名稱猜測變成自動出售候選或保留依據。不支援的整份存檔版本也不強行載入。

## 實際引擎量測：多多少掛機空間？

以下是 **2026-10-25 對實作完成的引擎執行的確定性量測**，不是把理想出售比例乘上容量的預測，也不是瀏覽器實際背景運行時長保證。

### 固定條件

- 種子 1–100，各自從新遊戲開始，在第 1 層以「均衡」自然通關 10 次。
- 每次通關立即回營，依武器、護甲、飾品順序，換上該部位現有裝備中屬性評分最高者；同分保留先遇到的物品。評分不含武器特效，這只是可重現測試策略，**不是最佳配裝建議**。
- 不賣熱身裝備，不注入等級、品質、數值或完美保留者；不重抽、不手動喝藥、不偷看後續掉落。
- 從同一份熱身後狀態複製三組：關閉；開啟但不新增鎖定；開啟並鎖定當下自然取得、沒有被另一件同型物品逐項嚴格壓過的備用裝備。第三組只用當下可見資料決定，額外鎖定件數為 5–16 件，中位數 9 件。
- 此後固定裝備及鎖定，不手動整理、不再換裝，連續重刷第 1 層，直到原本的近滿額保護回營。原有新手裝備的鎖定保留，但其身份不能作為安全出售依據。

### 100 個種子的觀察結果

下表是**熱身 10 次之後**的中位數；括號為最小–最大值。時間包含實際引擎模擬的戰鬥及通關間休息，不含熱身。

| 測量項目 | 關閉 | 開啟：只靠已裝備保留者 | 開啟：另鎖定自然備用裝備 |
| --- | ---: | ---: | ---: |
| 停下前追加通關 | 59（51–68） | 64（55–73） | 74（64–92） |
| 停下前模擬秒數 | 712.7（590.6–826.0） | 771.4（637.5–901.1） | 898.5（752.1–1087.5） |
| 新生成裝備件數 | 100（90–105） | 109（97–118） | 126.5（107–148） |
| 自動出售件數 | 0 | 9（1–16） | 27.5（12–47） |
| 僅出售取得的金幣 | 0 | 538.5（77–1097） | 1326（516–2893） |
| 含戰鬥獎勵的總金幣增量 | 4484（3876–5168） | 5347.5（4486–6453） | 6914.5（5608–9657） |

中位數可有半件／半枚，表示偶數樣本中間兩筆的平均；單次遊戲仍是整數。

**同種子配對比較**：只靠已裝備保留者，99/100 組多通關，追加改善中位數為 **5 次、60.0 秒**，另 1 組雖有出售但在同一次通關碰到安全停點。另鎖備用裝備的 100/100 組都多通關，配對改善中位數為 **15 次、173.2 秒**，範圍為多 7–32 次、81.4–362.1 秒。這些是配對差值的中位數，不等於兩欄中位數直接相減。

三組共 300 次長跑**全部仍然安全停止**：結束背包為 116–119/120 件，沒有戰敗或待領溢出。單獨啟用組總計售出 953 件、取得 52,782 金幣；另鎖備用組總計售出 2,750 件、取得 138,775 金幣。每種策略在 100 個起始狀態中合計 2,018 件既有物品（含已裝備）皆完整保留；各組完成上述鎖定設定、開始連續刷關後，鎖定狀態也未改動。

### 如何核對，而不是只相信數字

測試直接呼叫正式 `createGame`／`act`／`advance`，另放一個「關閉自動出售」的觀察副本，從每次相同的掉落前狀態取得完整新物品。每次掉落核對實際組與副本的戰鬥資料、RNG、ID、收入及保留結果；只同步副本，不修補或清理實際組。

- 關閉、只靠已裝備、另鎖備用三組，共同走過的**完整生成物品串與每一次 RNG 寫入串前綴完全相同**。開啟組走得更久後自然多出的尾段不是 RNG 回歸錯誤。
- 每件實際售出物品都有當下受保護的同型保留者，並由測試中的獨立六項逐項比較再核對；售價只加一次。
- 所有沒有售出的新掉落仍保有完整原始資料。這批觀察含優良以上、完全同值、升級與屬性取捨的留存案例；較小樣本不保證自然出現每一類，另外的規則測試也固定覆蓋這些邊界。
- 觀察機制另與完全未加觀察器的正式關閉組比對最終狀態，確認量測本身未改變結果。

### 重現方式與日常測試成本

在 `dot-game/` 執行：

```sh
# 日常回歸：固定種子 1、7、42、73、100；本次約 1.17 秒。
node --test tests/safe-loot-longrun.test.mjs

# 較廣量測：種子 1–100；本次約 18.49 秒，不預設塞進每次測試。
SAFE_LOOT_SEEDS=100 node --test tests/safe-loot-longrun.test.mjs

# 規則與操作邊界；獨立於長跑收益數字。
node --test tests/safe-loot.test.mjs tests/safe-loot-actions.test.mjs
```

長跑測試輸出每個種子的件數、金幣、通關與模擬時間，以及總結。日常 5 種子結果的通關中位數為 59／64／71；**不要拿它冒充 100 種子的 59／64／74**。執行時間依機器而異。

## 尚未解決的限制

這只能減少一部分背包壓力，不是無限掛機：優良以上、升級、同值、取捨、無保留者及無法辨識的物品都會累積。120 格容量、開始遠征須預留空間、近滿額回營與待領保護保持原樣；其他層數與配裝仍可能戰敗。僅第 1 層、上述固定策略的實測不能外推到所有玩法。

瀏覽器節流、休眠及關頁仍不會補算收益。本次只驗證出售收入與更晚碰到安全停點，**沒有解決金幣的長線用途，也沒有新增消費循環**；多取得金幣不代表養成深度已完成。
